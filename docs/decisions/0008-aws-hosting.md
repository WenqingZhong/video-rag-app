# ADR 0008: Hosting on AWS: one EC2 instance with Compose, Bedrock, S3, Terraform and GitHub Actions

- **Status:** accepted (infrastructure written and validated; first deploy pending)
- **Date:** 2026-09-29
- **Runbook:** [`infra/aws/README.md`](../../infra/aws/README.md)

## In one minute

The whole stack runs on **one ARM EC2 instance (t4g.large, 8 GB)** with Docker Compose. The heavy or stateful-elsewhere
parts move to managed services where it is cheap to do so:
- the language model runs on **Amazon Bedrock** (Claude Haiku 4.5), so the server needs no GPU;
- files go to **S3**;
- secrets go to **SSM Parameter Store**.

Everything is created by **Terraform** and deployed by **GitHub Actions**. About $57/month, plus Bedrock usage
capped at ≈ $0.70/day by the global token budget (ADR 0007).

## Options

| Option | Monthly (approx.) | Verdict |
|---|---|---|
| **ECS Fargate + RDS + ElastiCache + OpenSearch Service** | $250–350 | Rejected for now: Fargate for the API, workers and CLIP (~$150), plus a load balancer, NAT gateway, database, cache and search domain. Nothing here needs multi-AZ yet |
| **EC2 + Compose, local model on a GPU** (g5.xlarge) | ~$730 | Rejected: a GPU running all day for a demo's traffic |
| **EC2 + Compose, models on Bedrock** | ~$57 + usage | **Chosen:** the same Compose stack as local development; pay per token for the model |
| Lightsail / a VPS elsewhere | ~$40 | Rejected: no IAM roles, so S3 and Bedrock would need long-lived keys on the machine |

The code already talks to S3 through the S3 API and to models through a provider switch (`LLM_PROVIDER`), so each
piece can later move to its managed service without code changes (RDS: a URL; OpenSearch Service: a host).

## The design

| Decision | Why |
|---|---|
| **ARM (Graviton)** | ~20% cheaper than x86 for the same memory, and the Mac is ARM: images are the same architecture locally and in production |
| **No SSH, no open ports but 80/443**; administration through **SSM Session Manager** | No keys to lose; access is IAM-authenticated and logged |
| **Caddy** exposes `/app`, `/api/v1/chat*`, `/api/v1/me/*`, `/api/v1/health` only | Admin, trace, search, docs and metrics endpoints are unreachable from the internet, in addition to the admin token |
| Free hostname **`<ip>.sslip.io`** | HTTPS (Let's Encrypt) needs a name; this one resolves to the Elastic IP. A real domain is one variable |
| **IAM instance role** for S3, Bedrock, ECR and SSM; IMDSv2 with hop limit 2 | No AWS keys on the machine; containers can reach the role |
| Bedrock permissions **scoped to the Haiku 4.5 inference profile** | The server can't call other (more expensive) models |
| Secrets in **SSM Parameter Store**; `deploy.sh` writes `.env` (root-only) | One place to change a setting; generated by Terraform except the Pexels and Telegram keys, which are typed in by hand so they never touch a file or the Terraform state |
| **Refuse to start** in production with development secrets | A forgotten `SESSION_SECRET` would make cookies forgeable; better a failed deploy |
| **GitHub OIDC** role that trusts only `main` of this repository | No long-lived AWS keys in GitHub; a pull request can't deploy |
| Images tagged by **commit**, ECR tags immutable | What runs is exactly what was tested |
| Build on GitHub's **ARM runners** | Native builds; emulated torch builds take far longer |
| Deploy = **SSM Run Command**: fetch the bundle, write `.env`, `compose pull && up -d`, wait for health | No inbound access needed; the workflow fails if the API doesn't come up, and shows its logs |
| **Airflow → a cron container** | Airflow uses 1.1 GB for two nightly HTTP calls; the calls are the same admin endpoints |
| **Nightly `pg_dump` to S3**, 14 days | Postgres is the source of truth; the search index is rebuilt from it |
| **Memory limits** per service, 2 GB swap | One service's peak can't take down the others on 8 GB |
| Caches keyed by the **model actually used** | Found while preparing this: after switching to Bedrock, the answer cache would have served answers from the old model |

## The library

The 35 library videos are copied, not re-processed: `scripts/migrate_library.py` copies their files to S3 and their
rows (transcripts, captions, CLIP vectors) as CSV, and the server loads them and rebuilds the index. Tested locally
against a scratch database: 35 videos, 113 segments, 91 with vectors; a second run adds nothing. Their captions were
written by qwen2.5vl:3b; new uploads are captioned by Haiku 4.5.

## Consequences

- **One machine:** no redundancy. If it fails, `terraform apply` builds a new one and the data comes back from the S3
  backups (up to a day lost). Acceptable for a demo; the move to RDS and managed OpenSearch is the next step for
  real traffic.
- **Whisper and CLIP run on the CPU:** processing a video takes longer than on the Mac. The token budget, not the
  CPU, is what limits usage.
- **One Telegram bot, one poller:** the local bot must be stopped (or use a second bot token) once the server runs.
- **Terraform state is local** and contains generated secrets. A team would use an encrypted S3 backend with locking.
